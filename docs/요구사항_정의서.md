## 1. 도메인 선택과 조건 충족 근거

### 1.1 선택한 도메인

**화가** — 국적·시대 제한 없이, **한국어 위키백과에 문서가 있는 화가** 전체.

미술관에서 관람객이 도슨트에게 묻는 질문("이 연작은 몇 점이고 어디 있어요?", "이 그림은 어떤 사건을 그린 거예요?", "두 화가는 뭐가 달라요?")에 답하는 서비스다. 작품 수·소장처·연도·크기처럼 **구체적인 사실이 많고, 그럴듯하게 틀리기 쉬운** 분야라서 근거를 보여주는 RAG가 특히 필요하다.

### 1.2 조건 ① 항목 메타데이터 (약 100건 이상) — 충족: **1,343명**

| 항목 | 내용 |
|---|---|
| 출처 | Wikidata (SPARQL 조회) |
| 수집 조건 | 사람이고 · 직업이 화가(P106 = Q1028181)이고 · 한국어 위키백과 문서가 있음 → 2,054명 |
| 정제 | 위키데이터 직업에 부업도 포함되어 배우·가수가 섞임 → 한국어 소개에 '화가'(만화가 제외) / 영어 소개에 'painter' / 사조 정보 중 하나라도 있어야 인정 → **1,343명 유지, 711명 제외** (제외 목록 검수 결과 실제 화가 8명, 오류율 약 1.1%) |
| 속성 | 이름(한·영), 소개, 국적, 대륙, 출생·사망 연도, 활동 시기(세기), 출생지, 사조, 장르, 대표작, 유명도 순위(sitelinks), 위키백과 문서 제목·URL |
| 데이터 품질 | 사조 없음 601명(45%), 장르 없음 656명, 대표작 없음 620명. 정보가 빠진 화가는 덜 유명한 쪽에 몰려 있음 (상위 100명 중 사조 없음 4%, 501위 이하 64%) |
| 이용 조건 | **CC0 1.0** (자유 이용, 출처 표시 의무 없음 — 그래도 화가마다 Wikidata 주소를 기록하고 화면에 표시) |

### 1.3 조건 ② 외부 문서 출처 — 충족: **2종**

| 출처 | 얻는 방법 | 이용 조건과 기록 |
|---|---|---|
| **한국어 위키백과** (주 출처) | MediaWiki API — 질문마다 검색어 추출 → 후보 검색 → 선별한 문서의 본문 수집. 모든 화가가 한국어 문서를 가짐 (수집 조건) | **CC BY-SA 4.0** — 문서마다 제목·원문 URL·수집일·관련 화가를 저장하고, 근거마다 원문 링크 표시. 요청에 연락처를 담은 User-Agent, 요청 간격 1초 |
| **국립현대미술관 소장작품** (보조 출처, F2016) | 문화공공데이터광장 오픈 API (서비스 키 발급) — 학예사 작품 설명 108건 중 우리 화가 8명의 45작품 | 문화공공데이터광장 오픈 API 이용약관에 따름 — 작품마다 미술관 상세 페이지 URL을 저장하고 근거에 출처 종류("국립현대미술관 소장품")와 링크 표시 |
| (보여주기용) 작품 이미지 | Wikidata 작품 항목 · Wikimedia Commons · 위키백과 문서 속 이미지 (주소만 저장) | 파일마다 원본 페이지(라이선스 정보 포함) 링크를 저장하고, 이미지를 누르면 원본 페이지로 이동. 답변의 근거로는 쓰지 않음 |

### 1.4 조건 ③ 근거가 필요한 질문 — 충족: **7개 (실험으로 확인)**

근거 없이(같은 모델에 문서를 주지 않고) 답하게 했을 때 실제로 틀리거나 지어낸 질문들이다 (F2015 실험, `docs/F2015_RAG_전후_비교.md`).

| # | 질문 | 정답 (원문 근거) | 근거 없이 답했을 때 |
|---|---|---|---|
| 1 | 진환은 1941년에 어떤 미술 단체를, 누구와 함께 결성했어? | 조선신미술가협회, 문학수·이중섭·이쾌대 (국립현대미술관) | **"김환기와 동방미술가협회"** — 단체명·인물 모두 지어냄 |
| 2 | 피카소가 가장 좋아한 음식은 뭐야? | 문서에 없음 → "확인되지 않는다" | **"빠에야를 즐겨 먹었다"** — 근거 없는 내용을 사실처럼 답함 |
| 3 | 이중섭의 은지화는 어떤 재료와 도구로 그렸어? | 양담배갑 은박지, 철촉필 (국립현대미술관) | **"은박지에 연필이나 먹으로"** — 도구가 틀림 |
| 4 | 게르니카 폭격 때 사상자는 몇 명이었고, 어느 부대가 폭격했어? | 사망 1,654명 · 부상 889명, 콘도르 군단 (위키백과) | "약 1,600명" — 수치가 부정확, 부상자 누락 |
| 5 | 김홍도의 단원 풍속도첩은 지금 몇 점이고, 처음엔 몇 점이었어? | 25점, 구입 당시 27점 (위키백과) | **"처음엔 30점이었는데 일부가 분실됐다"** — 점수도 틀리고 이유도 지어냄 |
| 6 | 게르니카는 지금 어디에 있고, 크기는 얼마야? | 레이나 소피아 국립 미술관, 349.3 × 776.6cm (위키백과) | 소장처는 맞혔고 크기는 "약 7.8m × 3.5m"로 어림값만 — 정확한 수치·출처 없음 |
| 7 | 모네의 수련 연작은 몇 점이고, 오랑주리 미술관에는 몇 점이 있어? | 약 250점, 8점 (위키백과) | 맞힘 — 유명한 사실은 모델도 앎 (대조군) |

### 1.5 위험 도메인 여부

화가·미술 정보는 건강·금융처럼 판단을 잘못했을 때 위험이 큰 도메인이 아니다. 따라서 **전문가 조언을 대신하지 않는다는 면책 안내는 두지 않는다.** 대신 모든 답변 화면에 "수집된 문서만 근거로 답하며, 문서에 없는 내용은 확인되지 않는다고 답한다"는 안내를 둔다.

## 2. 서비스 개요

| 구분 | 내용 |
|---|---|
| 사용자 | 미술관 관람객, 미술에 관심 있는 일반인, 미술사 공부를 하는 학생 |
| 핵심 가치 | ① 출처가 있는 답 ② 모르는 것은 모른다고 하는 답 ③ 작품 이미지와 함께 보는 화가 정보 |

## 3. 기능적 요구사항

명세서의 필수 기능(F2001~F2012)은 내용을 바꾸지 않고, 표현만 화가 도메인에 맞게 구체화했다. 심화 기능(F2013~F2016)은 네 개 모두 선택했고, 자체 추가 요구사항 1개(F2017)를 두었다.

| 번호 | 분류 | 요구사항명 | 요구사항 상세 (화가 도메인) | 우선순위 | 상태 |
|---|---|---|---|---|---|
| F2001 | 데이터 | 항목 메타데이터 적재 | 화가 1,343명의 메타데이터(`data/painters.json`)를 로드하고, 화가 1명을 이름·소개·국적·대륙·생애·활동 시기·출생지·사조·장르·대표작이 담긴 색인 텍스트 1개로 구성한다. | 필수 | ✅ |
| F2002 | 색인 | 메타데이터 색인(RAG 1) | 화가 색인 텍스트를 임베딩하여 `painter_meta` 컬렉션에 화가 ID(위키데이터 ID)를 청크 ID로 색인한다. 다시 색인해도 중복 저장되지 않고, 저장된 청크 수를 확인할 수 있어야 한다. | 필수 | ✅ |
| F2003 | 프롬프트 | 검색어 추출(프롬프트1) | 미술사 큐레이터 역할 프롬프트로, 화가 정보와 질문에서 한국어 위키백과 검색어를 JSON 배열로 추출한다. 화가 본인의 위키백과 문서는 항상 검색 대상에 포함한다. | 필수 | ✅ |
| F2004 | 수집 | 외부 문서 수집(프롬프트2) | 검색어마다 위키백과 후보(제목·요약)를 모으고, 선별 프롬프트로 관련 문서만 골라 본문과 원문 URL을 수집한다. 화가 본인 문서는 선별·길이 규칙보다 우선해 항상 수집하고, 이미 수집한 검색어는 다시 수집하지 않는다. | 필수 | ✅ |
| F2005 | 색인 | 외부 문서 색인(RAG 2) | 수집한 문서를 청크 크기·중복 길이(기본 1,000자/200자, `config.py`에서 조정)로 나누어 `painter_wiki` 컬렉션에 색인한다. 청크에는 문서 제목·원문 출처·관련 화가를 저장하고, 청크 ID는 `화가ID:문서ID:순번`으로 한다. | 필수 | ✅ |
| F2006 | 검색 | 근거 검색 및 병합 | 선택한 화가의 메타데이터 청크는 항상 근거에 넣고, 외부 문서 청크는 그 화가로 범위를 좁혀 유사도로 검색한다. 두 결과를 병합하고 중복 청크를 제거한다. 근거 수(Top-k)는 설정으로 조정한다. | 필수 | ✅ |
| F2007 | 생성 | 근거 기반 답변 생성(프롬프트3) | LangGraph를 retrieve·generate 두 노드로 구성하고, 미술관 도슨트 역할의 답변 프롬프트로 검색된 근거만 사용해 답한다. 근거에 출처 종류(화가 메타데이터/위키백과/국립현대미술관 소장품)를 구분하고, 근거가 없으면 "제공된 문서에서는 확인되지 않습니다"라고 답한다. | 필수 | ✅ |
| F2008 | 생성 | 근거 표시 | 답변의 주요 주장에 `[근거 N]`을 표시하고, 실제로 인용된 근거만 제목과 원문 링크로 보여준다. 인용된 근거가 없으면 그 사실을 안내한다. | 필수 | ✅ |
| F2009 | UI | 항목 선택 및 질의응답 | 1,343명 화가 목록에서(이름 검색 가능) 화가를 고르고 채팅으로 질문·답변을 주고받는다. 대화 기록은 화가별로 따로 유지한다. | 필수 | ✅ |
| F2010 | 서비스 | 도메인 특화 기능 | **화가 비교**: 두 화가와 비교 관점을 고르면, 화가별로 수집·검색한 근거만으로 비교표와 공통점·차이점을 만들고 칸마다 근거 번호를 붙인다. | 필수 | ✅ |
| F2011 | 서비스 | 조건 기반 항목 탐색 | "19세기 프랑스 인상주의 풍경화가"처럼 자연어 조건을 입력하면, 조건 해석 → 메타데이터 필터 → LLM 검증으로 조건에 맞는 화가만 카드로 보여주고, 카드를 누르면 그 화가와의 대화로 이어진다. | 필수 | ✅ |
| F2012 | UI | 진행 상태 및 안내 | 문서 수집·답변 생성 중 진행 단계를 표시하고, 색인이 없거나 API 키가 없을 때 안내한다. 화가 도메인은 위험 도메인이 아니므로 면책 안내는 두지 않는다. | 필수 | ✅ |
| F2013 | UI | 프론트엔드 직접 구현 | HTML·CSS·JavaScript로 화면을 구현하고(FastAPI 서버와 분리), 요청·응답 형식을 정의한다. 질문 입력·답변·근거 표시를 모두 제공한다. | 심화 | ✅ |
| F2014 | 검색 | MMR 검색 적용 | 후보를 넉넉히(20개) 가져와 다양성을 고려해 근거(5개)를 고르는 MMR 검색을 제공하고, 유사도 검색과의 근거 차이를 화면에서 비교할 수 있게 한다. | 심화 | ✅ |
| F2015 | 품질 | RAG 전후 품질 비교 | 근거 없이 답하면 틀리기 쉬운 대표 질문 7개를 RAG 사용 전후로 답하게 하고, 사실 정확성·근거 제시·모름 인정 기준으로 비교한 문서를 작성한다. | 심화 | ✅ |
| F2016 | 수집 | 여러 문서 출처 결합 | 한국어 위키백과와 국립현대미술관 소장작품 설명을 함께 색인하고, 근거에 출처 종류를 구분해 표시한다. 출처별로 수집·청킹 방식을 달리한 이유를 설명한다. | 심화 | ✅ |
| F2017 | UI | 작품 이미지 표시 | 화가별 대표작 이미지(위키데이터 작품, 유명한 순 최대 40점)와 위키백과 문서 속 관련 이미지를 갤러리로 보여주고, 원본 페이지(출처·라이선스)로 연결한다. 공개 이미지가 없는 화가(저작권 보호 작품)는 이미지를 가져오지 않고 국립현대미술관 작품 페이지 · e뮤지엄(한국 화가) · Google Arts & Culture · 이미지 검색으로 연결한다. 이미지는 답변의 근거로 쓰지 않는다. | 추가 | ✅ |

## 5. 요구사항 상세 (수용 기준)

각 요구사항이 충족되었는지 판단하는 기준이다. 검증 방법은 명세서 4장의 확인 항목을 따르며, 실행 결과는 검증 결과 문서와 캡처로 제출한다.

### 데이터 · 색인

| 번호 | 수용 기준 | 확인 방법 | 구현 위치 |
|---|---|---|---|
| F2001 | 로드한 화가 수가 1,343명이고, 화가 1건의 색인 텍스트에 의도한 속성이 모두 들어간다 (빈 값은 줄째로 생략) | `python -m data_prep.painters` | `data_prep/painters.py` |
| F2002 | 색인된 청크 수가 화가 수(1,343)와 같고, 두 번 실행해도 늘지 않는다 | `python index_meta.py` 두 번 | `index_meta.py`, `vectorstore/store.py` |
| F2005 | 청크 크기·중복 길이를 설정에서 바꾸면 청크 수가 달라진다 (1,000/200 → 500/100: 240 → 505개, 되돌리면 240개). 두 화가가 같은 문서를 수집해도 청크 ID가 겹치지 않는다 | `python index_wiki.py` + `config.py` 변경 | `index_wiki.py` |
